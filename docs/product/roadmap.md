## Done

Compile-checked and linted only; not tried in a browser.
- (2026-11-07) Cycle migration, phase 2 (front): the teams page replaces the date picker by a "which rotation day is this team on today" dialog (`PUT /teams/:id/cycle-position`, swap offered when the day is taken, anchor created on first use); warnings when the team count differs from the active rotation's days (teams page) and, per rotation, from the center's team count (rotation page). Position endpoint tested on a scratch database (conflict, swap, range, equivalence with `computeShiftOfTeam`); front only compile-checked and linted, not run in a browser.
- (2026-11-07) Cycle model migration, phase 1 (expand): `Center.cycleAnchorDate` + `Team.cycleOffset` added next to `Team.cycleStartDate`; every reader goes through `utils/teamCycle.js` (offset first, legacy date as fallback), so nothing changes until a center is migrated; `scripts/migrateCycleOffsets.js` migrates center by center. Tested on a scratch database (8-team center migrated with 1072 shift computations identical before/after, 3 anomalous centers blocked, rollback clean); dual-write in the legacy endpoint is only syntax-checked and exercised on an unmigrated center.
- (2026-11-05) Team grid: period changes are animated with Swiper (previous/current/next slides, names column fixed, data for the three periods fetched in one call, endpoint cap raised to 93 days); mobile only offers 6 days; names capped in width and shown as last name in capitals. Compile-checked and the endpoint timed (72 days in ~350 ms); not tried in a browser.
- (2026-11-05) User shift computation and the rotation page now agree: `computeUserShifts` resolved ONE rotation for a whole date batch (the one active on the batch's last day), so any range containing an activation date (a calendar month, the team grid) showed the new rotation before its activation. It now picks the rotation active on each day (last activation <= the day, same rule as `findLatestRotation` and the rotation page's status), loading each center's activation timeline once. Checked against the local database: 471 days compared with `computeShiftOfTeam`, 199 mismatches before, 0 after.
- (2026-11-05) Teams page: team cards show the current day of the planning cycle (Temporal, center time zone) and two icon buttons (member timeline, grid); the cycle start dialog uses `base-dialog`; `getNextCycleDate` moved to Temporal. New team grid page `/center/:centerId/grid` (6/12/24 days, one cell per member per day with the shift or entry, replacement/switch counterpart names, names column fixed with swipe navigation) backed by `GET /teams/:id/grid` (31 days max). Only compile-checked (Vue SFC compiler, `node --check`); not run in a browser or against MongoDB.
- (2026-11-05) Rotation activation dates must be today or later in the center's time zone (Temporal, `Center.timeZone`): otherwise 400 `ROTATION_ACTIVATION_DATE_PAST`; the activation dialog's date picker greys out past days using the center's time zone (computed with Temporal; `@js-temporal/polyfill` added to `front/package.json`), which `GET /center` now returns as `timeZone` (harmless, and needed by the front). Removing a date is unchanged. Syntax-checked only.
- (2026-11-05) Same-date activations refused (known issue #34): adding an activation on a date where any rotation of the center already has one answers 400 `ROTATION_ACTIVATION_DATE_TAKEN` (`rotationActivationService.js`), for preview and confirm. Syntax-checked only; existing duplicates in the database are not cleaned up.
- (2026-11-05) Rotation change no longer swallows errors in `convertCenterDemands` (known issue #33): cancel/withdraw failures now abort the transaction and are reported, and the demand is re-read after a withdraw before applying poster/switch changes (no stale save). Syntax-checked only; not run against MongoDB.
- (2026-11-05) `centerId` is now carried by the access token (`generateAccessToken`, set at login and refresh) and `centerAuth.js` reads role and center from it instead of querying `User` on every guarded request. Tokens issued before the change have no `centerId` and get 403 from the guards until refreshed. Not run against MongoDB, no tests exist.
- (2026-11-05) `centerAuth.js` simplified: one place loads the caller (`resolveCenterId` moved in from `authMiddleware`, `announcementAuth.js` replaced by `authorizeAnnouncementAccess` via the new `masterOnlyField` option), the `'admin'` user mode and the per-guard custom error texts removed (generic messages). Behavior unchanged except wording; a global announcement that also carries a center is now covered by an explicit test.
- (2026-11-05) Guards consolidated in one file and the center moved into the URL: `middleware/rotationAuth.js` removed (its guard now lives in `middleware/centerAuth.js`), `authorizeBodyCenter` removed. Creations are `POST /rotations/center/:centerId` and `POST /teams/center/:centerId` (replacing `/rotations/create`, `/teams/create-team`); announcements are `POST /announcements/send` (global, master only) and `POST /announcements/center/:centerId/send` (the "global" notion comes from the route, not from a body flag). Front services updated accordingly.
- (2026-11-05) **Credentials no longer leave the server**: `GET /users`, `GET /users/center/:id` and any `res.json(user)` returned each user's bcrypt hash, live refresh tokens and password-reset token to any logged-in user; `models/User.js` now strips them at serialization.
- (2026-11-05) Missing-token endpoints resolved per route: `POST /messages` and `POST /tickets/status/:id` need a token; `GET /teams/:centerId` is authenticated and center-scoped with a separate public `GET /teams/public/:centerId` (id and name) for sign-up; `GET /users/info/:email` no longer reveals the role; `GET /users/devlist` is 404 in production; stats, contact tickets, check-email and OTP stay public by design (known issue #6).
- (2026-11-05) Center-scoping helpers in `middleware/centerAuth.js` (resource by id, body center, id lists, three user modes) applied to users, teams, tickets, demands, rotations and announcement sending; fixed on the way: any admin could act on any user, anyone could change anyone's avatar, any local admin could email every user (`isGlobal`), `GET /users` returned every user to any logged-in user. `isUserOrAdmin` and `checkUserCenter` removed.
- (2026-11-03) Rotation activation: preview and confirm merged into one endpoint per action (`/activate`, `/remove-date`, `confirmed` boolean in the body) and one front service call each (`setActiveRotation(id, date, confirm)`, `removeActivationDate(id, date, confirm)`); the `/confirm-activate`, `/confirm-remove-activate` aliases and their compatibility shim are gone; `confirmed` must be a real boolean.

- (2026-11-03) Center API secured: create/update/delete and cross-center reads are master-admin only, active rotation limited to the center's members, and the one public route (`GET /center`) no longer leaks admin user ids, related centers or time zones (known issue #3; new issue #38 for the delete handler).
- (2026-11-03) One-year team timelines: team members drawer (past, current and upcoming members, reinforcements hatched) and the user's own teams in `UserTeamCard`; new endpoints `GET /users/teams/:centerId/timeline` and `GET /users/:id/team-timeline`, `buildTeamTimeline`, `middleware/centerAuth.js`.
